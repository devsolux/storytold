# EffectCraft

## Choose this app

Motion graphics, compositions and keyframes. Native server key: `effectcraft`. Plugin-provided or
host-specific namespacing may change the callable tool prefix; discover it.

## Launch and scope

Native executable: `effectcraft-cli` (`.exe` on native Windows). On macOS the `.app` (from
the `.dmg` or the ArtCraft Launcher) holds only the desktop app: install the separate
`effectcraft-cli-<version>-macos-universal.zip` release asset. Windows MSI/portable ZIP and
Linux `.deb`/`.rpm` packages install the CLI next to the app (Linux: `/usr/bin/effectcraft-cli`).
The source-derived launch arguments live in the single reviewed
[app catalog](../../../../config/apps.json), not in a copied engine registry.
Native source documents distinct read/write roots; still test the pinned binary and OS boundary.

## Discover before execution

Discover compositions, layer/property schemas, keyframe operations, native batches and frame/export jobs. Use the native progress/status APIs where present (progress notifications, renderQueue.list/renderQueue.stop) rather than adding a queue. Tools include get_project, get_comp, get_layer, get_property, set_property, add_keyframe, render_frame, save_project, batch and command_batch. Since 0.25.x render_frame and render_preview take `times` (1 to 64 comp times in seconds, not with `time`) and return one contact-sheet PNG tiling those frames row by row in the order given: `columns` (default near-square), `labels` (default true, each cell's time), `max_side` per cell (default 320; a sheet is at most 7680 px a side); the metadata gives comp, times, columns, rows, cellWidth, cellHeight, width and height. `columns` or `labels` without `times` is an error; render_frame writes a sheet to `path` only headless, checked like a frame's output (bridged, inline only).

## Workflow and risky operations

The source-documented read/write roots enable restricted mode that refuses scripting and UI/control tools and, since 0.22.0, plug-in installs (effect.plugins.install), the Plug-in Library (library.*, which downloads code) and external effect helpers (effect.helpers.scan/load, native child processes), and since 0.25.x Watch Folder (file.watchFolder and .poll, which render to the outputs the found projects name), Edit Original (edit.editOriginal) and answering a script's file dialog (scriptui.fileDialog). Do not bypass it. Both roots must exist at launch; without a write root nothing is written. Keyframe-setting time may be layer time while sampling/render time is composition time; use the tool-specific timeBase when required. Layer and comp ids may be sent as strings; an all-digit string that matches no name is taken as an id. The viewer-resolution commands (view.res.*) change the saved project without an undo step. Since 0.13.0 anim.applyPreset and the property and link paste commands resolve effects/<match name>[#n]/<property> paths (the form presets and copied links carry) to the layer's effect instead of falling through silently; keys.delete returns the number of keys actually removed, so 0 means nothing changed. Since 0.17.0 the prop.* commands behind get_property, set_property and add_keyframe take that path form too; deleting a layer also clears, in the same undo step, every layer-reference property and key that named it (Set Matte, Clone Source, a light's Environment Source…); edit.splitLayer puts the new part above the original by default (general.createSplitLayersAbove); layer.replaceSource {item, layers} swaps a layer's source and keeps the rest (a comp can't contain itself). Since 0.23.0 a text layer's name follows its text (layer.setText renames it) until the layer is renamed, and the CC, Keylight, Lumetri and Mocha effects show descriptive labels (ids and old names still resolve), so address layers and effects by id. Since 0.25.x the parameters that pick channels (EXtractoR's Red/Green/Blue/Alpha, Cryptomatte's Layer and Layer Name, 3D Channel Extract's 3D Channel, ID Matte's Aux. Channel, IDentifier's Channel Type) can't be animated: add_keyframe, set_property with `time` and expressions on them are refused (set_property without `time` sets the value), and a document that animated one opens with its first value and says so; expressions and scripts number a layer's top-level groups as After Effects does (1 is the markers, unused slots are empty groups).

## Durable verification

Check composition dimensions, timing, layer offset/stretch, expected frames and media. Preserve native warnings. batch rolls back when a step fails, while command_batch keeps one undo step per edit and stops at the first error; neither spans files or apps. Autosave is not enabled implicitly. A project saved by 0.13.0 also records each comp's current time (compTimes, editor state beside activeComp/openComps; older versions ignore it) and reopens there, so read the time back instead of assuming a reopened comp sits at 0. Since 0.11.1 a footage path stored in a project resolves beside it and is followed only on this computer or the project's own share; any other (a device or a non-file URL too) is marked missing without being read, so list missing footage with file.findMissing after opening. Since 0.17.0 an imported 3D model's side files (buffers, textures, MTL) follow the same rule. By 0.21.1 the confined headless session reads footage, and files an import pulls in, only inside the read roots (others show as missing), and renderQueue.add, render.preRender and file.createProxy without an output need a saved project. A render output never replaces footage, a proxy or the project file, and two queue outputs on one file refuse the whole render (isError) naming both; file.checkOutput {path} reports beforehand, and render_frame with a path follows the same guard. Since 0.24.1 a render is also refused when its output folder, or an existing numbered folder of a template such as shot_[###]/f_[#####].png, holds a symbolic link leading outside the write roots, and a confined batch step's params must be an object, not a $N reference. help.exportRepro needs an explicit path in a write root; journal.export {} returns the repro in memory (0.24.0). Since 0.22.0 file.exportAep {path, allowLosses?, dryRun?} writes an After Effects project and refuses a lossy one unless allowLosses (dryRun returns the report); since 0.24.0 file.import takes .aep/.aepx too. command_list and list_effects take compact: true; popup properties report options [{value, label}] (0-based). A numbered still imports as one frame unless file.import gets sequence: true; since 0.23.0 a gap in a sequence's numbering holds the previous frame. Since 0.25.x a multi-layer OpenEXR shows only its unprefixed R/G/B(A) (else Y as grey), so a file of named layers only (Blender's ViewLayer.Combined.R) renders black: read its passes with layer.channels and EXtractoR. Editing a layer's masks, the effects above it or a precomp's contents now also clears a Warp Stabilizer or 3D Camera Tracker analysis (headless: run warp.analyze or camera.analyze again).
