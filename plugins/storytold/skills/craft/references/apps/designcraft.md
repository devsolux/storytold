# DesignCraft

## Choose this app

Page layout, stories and publishing. Native server key: `designcraft`. Plugin-provided or
host-specific namespacing may change the callable tool prefix; discover it.

## Launch and scope

Native executable: `designcraft-cli` (`.exe` on native Windows). On macOS the `.dmg` app bundles the CLI
since 0.17.1 (`DesignCraft.app/Contents/MacOS/designcraft-cli`, not on `PATH`); the separate
`designcraft-cli-<version>-macos-universal.zip` asset is still published. Windows MSI/portable ZIP and
Linux `.deb`/`.rpm` packages install the CLI next to the app (Linux: `/usr/bin/designcraft-cli`).
The source-derived launch arguments live in the single reviewed
[app catalog](../../../../config/apps.json), not in a copied engine registry.
Native source documents distinct read/write roots (since 0.9.0); still test the pinned binary and OS boundary.

## Discover before execution

Discover document structure, story reading/editing, image placement, page rendering, save and export. Tools include inspect_document, get_story, set_story_text, place_image, render_page, save_document and export_png; PDF, IDML, EPUB and PowerPoint (file.exportPptx, since 0.9.0) export run through execute (for example file.exportPdf; standard x1a, PDF/X-1a:2003, since 0.14.0). Since 0.18.0 file.exportBatch exports chosen alternate layouts in several versions (PDF, PNG, JPEG) at once: a file per layout and version, in a folder per version under `dir` (inside the write root), or base64 in the reply without `dir` (512 MiB at most); dryRun lists the names; presets saved with file.saveExportPreset last only for the headless session. Inspect the running schema. A tool argument or an execute/batch params key the command does not take is refused (JSON-RPC -32602), and batch checks every step before the first runs; since 0.17.1 the input schemas are closed and keys are checked at every listed level (a batch step, a pointer event), the error naming the path (`commands[0].parms`), and all four MCP hints are set (read-only: list_commands, inspect_document, get_story, menu_list, ui_inspect). A panic outside a command is a tool error and the server keeps running. Since 0.21.1 the stdio framing is the shared craft-mcp-server (still protocol 2025-06-18, also 2025-03-26 and 2024-11-05): after the -32602 key check, required arguments, top-level types and enums are checked against tools/list before the tool runs (a failure is an isError tool result); a message without "jsonrpc": "2.0" is refused, a JSON-RPC batch holds at most 1000 messages, and a request line over 4 MiB is refused (-32600) while the server keeps serving, so place a base64 image over about 3 MiB from a path instead. Since 0.21.1 place.load {files: [{path | base64}], append?} queues up to 1000 images for place.grid {rect, columns, rows, gutter} or place.contactSheet (all of them on new pages, one undo step). render_page and export_png page 0 is the first page, position 1 in file.exportPdf's pages.

## Workflow and risky operations

Text positions are UTF-8 byte offsets, not character counts or JavaScript string lengths. Compute a boundary with len(prefix.encode("utf-8")) only when the native schema requires it. Since 0.10.0 story.replaceRange refuses an offset inside a character, an end past the story or start > end (the error gives the story length in bytes and nothing changes) where 0.9.0 snapped and clamped; in text parameters \u000b is a forced line break like \n. Since 0.13.0 find.find and find.change in document scope also reach table cells: such a match carries cell {table, row, col} and its start/end count from the cell's text; since 0.20.0 a GREP pattern with subroutine calls or recursion (\g<…>) is refused. Since 0.20.1 a table command whose params list story? and table? also runs with nothing in a table selected when given table (the id table.insert and table.get return); since 0.21.1 a table id that several stories hold needs story ("specify `story`"), and a story or table that is not a nonnegative integer (null included) is an error. Since 0.21.1 get_story (story.get), story.setDirection, type.fillWithPlaceholder and file.exportText refuse a story or frame id the document lacks (no such story N, no such frame N; both are checked, story wins) and a frame holding no text (Fill with Placeholder Text converts it), where they fell back to the selection. Coordinates use points and spread space; render_page and export_png page indices are 0-based. Commands that create items take spread: a body spread index, or {"kind": "parent", "index": n} for a parent spread (its index in the parents list of inspect_document); any other value is an error. batch stops at the first error (failedIndex) and earlier steps stay applied. Since 0.13.0 a type size outside 0.1 to 1296 pt and an Insert Pages count outside 1 to 9999 are refused. Since 0.19.0 layout.pages.delete and layout.pages.applyParent take 0-based page indices, refuse one past the last page or an entry that is not a whole number (where they skipped it), and return how many pages they deleted or applied. Since 0.21.1 type.align without a value, and object.stroke, object.textFrameOptions, type.para and paragraph-style values out of range or naming no option (spacing, justification, autoLeading, singleWordJustify, columns, inset), are refused, naming the key; hyperlink.create, hyperlink.edit and button.set refuse a url that is not http://, https:// or mailto:, and PDF export leaves any other link target out; a save whose file would not reopen fails ("the document would not reopen: …") and writes nothing. Since 0.21.1 data.placeholder.add puts an image field at a text insertion point as an inline image (scaled down to fit the frame); in a table cell or a note it inserts a `<<name>>` marker that merges as text, so an image field there needs role text and a hyperlink field is refused; a QR field still binds to a frame (item). The catalog launches mcp with --automation-read-root (the workspace) and --automation-write-root (outputs/): every open, place, relink, load or import with a path, and the files a document names (links, data sources, book chapters, Document Fonts), must read inside the read root, so a stored path outside it reads as missing; every save, export, package, book and library write inside the write root; a refused path is an ordinary tool error (automation path rejected). Both folders must exist at launch, --connect with them is an error, and the desktop app is never confined; since 0.13.0 each flag may be repeated to add a folder of its kind (a path inside any one passes, their common parent does not). Since 0.21.1 on Windows a network path (`\\server\share`, `\\?\UNC\…`, WebDAV `\\host@SSL\…`), a device path (`\\.\…`) or a verbatim path that is not a disk is refused by its name before the file system is asked, unless a root is on that same server and share (or verbatim prefix), as are a link whose target is one, a `\\?\` path holding `..`, a name ending in a period or a space, COM¹ to LPT³ and a device name before a colon. Not covered: path-less commands, the system font scan (also font.reload, 0.10.0, which rescans the installed font folders on request), the recovery folder, and file.print, which hands a PDF to the system print spooler. layout.parents.delete {id} (0.10.0) removes a parent spread's shared artwork and its assignments in one undoable step; local overrides stay as ordinary items. Since 0.11.0 the PDF reader is the shared craft-pdf backend with a 512 MiB input bound: file.place (place_image) and links.relink, links.relinkFolder and links.update refuse a larger PDF before parsing it, as an ordinary tool error naming the command or the path; the bound applies to PDFs only. Since 0.13.0 links.update, links.relink and links.relinkFolder also refuse, by name, any linked file over 256 MiB before reading it, and links.relinkFolder takes only a file directly in the chosen folder. Since 0.20.1 a whole-file read refuses a device or pipe and any file over 4 GiB. Since 0.21.1 a graphic placed from a path (place_image, file.place, place.load; IDML and INDD imports too) is linked, not embedded: the document keeps the path (absolute and relative), a proxy of at most 1024 px and a SHA-256 hash, saves as format version 5, which 0.20.x and older reject, and reads the file again, through the read root and up to 1 GiB, whenever a render or export needs it; a changed file exports as it now is and a missing one from its proxy, each with a warning (links.list storage and status; Preflight missingLink, modifiedLink). Embed with execute file.place {path, embed: true} (place_image has no embed argument), base64 or links.embed, or write a portable copy with file.saveACopy {embedLinks: true} (fails on a missing or changed link) or file.package; links.unembed {asset, dir?} links an embedded graphic to its original file, or writes it into `dir` (inside the write root) when that file no longer holds its bytes. Opening an older document from a path turns each embedded image whose file still holds the same bytes into a link at the next save. Since 0.21.1 a raster placed at its natural size (no width) takes the resolution stored in the file (a 600 px image at 600 ppi is 72 pt wide), one point per pixel when it stores none or an implausible one.

## Durable verification

Inspect overset text, fonts, linked images, pages and exported layout. Since 0.9.0 a path stored in a document (links, data sources, book chapters, IDML package links) resolves beside it and is followed only on this computer or the document's own share; any other reads as missing, with the reason in links.list and Preflight. Since 0.10.0 file.package writes the packaged document's and IDML's links relative to the package (Links/<name>), which resolve beside the document when it is reopened; links.copyTo still relinks the open document by full path. Since 0.13.0 file.exportPdf keeps a placed PDF's Object Layer Options choice as vector optional content and fails, naming the placed file, when that choice cannot be preserved safely or names a layer the file no longer has (recoverable layer problems become warnings); file.exportIdml with embedImages false refuses a document holding such a choice. Only standard a2b still rasterizes those PDFs, failing since 0.11.0 with the placed file and the reason (a missing page, layers that could not be hidden, an undecodable image, an unsupported font, truncated content) and otherwise warning "N placed PDF(s) with hidden layers exported as images". Since 0.17.1 `script --export` on the CLI prints the export's warnings to stderr as `run` does, and an option missing its value is refused when the next token is another option; since 0.21.1 `script --keep-going` still runs every step but then exits with an error naming the first failed step and skips --save and --export. Since 0.14.0 file.print spools exactly the PDF file.exportPdf writes with the same settings and returns its warnings, and ink.separations (a query) separates a page's spread as that PDF prints, with each ink's coverage, the maximum total ink and areas over inkLimit. Validate the actual saved/exported file and render relevant pages. CLI export options may apply only to following exports; do not use shell fallback without an explicit unique need.
