# PdfCraft

## Choose this app

PDF inspection, operations and validation. Native server key: `pdfcraft`. Plugin-provided or
host-specific namespacing may change the callable tool prefix; discover it.

## Launch and scope

Native executable: `pdfcraft-cli` (`.exe` on native Windows). On macOS the `.app` (from
the `.dmg` or the ArtCraft Launcher) holds only the desktop app: install the separate
`pdfcraft-cli-<version>-macos-universal.zip` release asset. Windows MSI/portable ZIP and
Linux `.deb`/`.rpm` packages install the CLI next to the app (Linux: `/usr/bin/pdfcraft-cli`); the
release also publishes a standalone `pdfcraft-cli-<version>-linux-x86_64.tar.gz`, which `setup` prefers.
The source-derived launch arguments live in the single reviewed
[app catalog](../../../../config/apps.json), not in a copied engine registry.
The catalog launches `mcp` with `--automation-read-root` (the workspace),
`--automation-write-root` (outputs/) and `--root` (the workspace). Both kinds apply (since 0.9.0),
so reads stay in the workspace and writes in outputs/; still test the pinned binary and OS boundary.

## Discover before execution

Discover actual PDF tools; compact mode may expose tool_search/tool_call rather than every operation. The pinned build must include MCP support (on by default in releases). Compact mode lists fifteen core tools (doc_open, doc_info, doc_inspect, doc_save, doc_close, doc_combine, doc_split, edit_undo, page_render, render_preview, text_extract, text_find, command_list, command_run, command_batch) plus tool_search and tool_call; tool_call reaches all 208 tools by name (page_duplicate takes an optional at; doc_set_info also sets custom properties, which doc_info lists under custom; layer_set is a view setting page_render follows that leaves the file unchanged; object_move takes all: true instead of objects; added in 0.19.0–0.21.0: OCR review (ocr_words, ocr_review_apply, ocr_dictionary), comments_copy/comments_paste (XFDF text), object_copy/object_paste, text_replace, text_prepare, page_enhance_scan, print production (doc_convert_colours, doc_fix_hairlines, doc_printer_marks, printer_papers), js_event and form_focus (a field's pointer and focus scripts), attachment_edit, comment_popup and accessibility_layout_table_to_blocks). page_render and render_preview follow the PNG with a JSON warnings part when the render was incomplete. A JSON-RPC line over 16 MiB is answered with -32600 and skipped. Inspect document and page structure before choosing edits.

## Workflow and risky operations

Every file a tool reads must lie inside the read root (attachment_add and model_add embed the file they read; bookmark_import reads a JSON file; ocr_dictionary reads an `ocr-dictionary-<language>.txt` file and, with add or remove, rewrites it, so it must then lie in the write root) and every file it writes (doc_save, also in place, extracts, splits, exports, bookmark_export out, doc_bates_multi outputs, the editable out of ocr_recognize and ocr_review_apply, always a new file, reports, signing output) inside the write root, so save to outputs/, never over an input; a refused path is an ordinary tool error (automation path rejected). Since 0.20.0 nothing outside the root or its parent folders is looked up before a path is refused. A tool refuses an input file over 512 MiB, and on Windows a path on another network share or device namespace than the root's is refused by name, without contacting the host. Without directories, text_font_files searches the read root, not the installed fonts. Edits stay in memory until an explicit doc_save; saving in place appends an incremental update that keeps the original bytes, except after redaction, sanitizing, removing an XFA form or an encryption change, and for a file whose cross-reference index had to be rebuilt on open, which are written in full (the result's incremental field says which happened). A save never replaces a read-only file (refused before anything is written) and keeps a replaced file's Unix mode and group, macOS/Windows creation date, macOS extended attributes (a save that cannot copy them is refused and the file kept, so save to a new path) and Windows hidden/system attributes. A doc_save to a path that already exists in the write root replaces that file without asking, so ask before reusing a name; over a hard-linked name it writes a separate new file and leaves the other link alone (observed). No save, extract, split or combine writes a value typed into a Password field; it stays in memory only. A document whose security forbids copying keeps its text from the text tools (text_lines too; ocr_recognize then leaves it out), content_copy, doc_compare and the redaction audit's covered text, and pdfa_convert needs the owner password of an encrypted file. doc_close refuses a document with unsaved changes, a new or recovered one even after undo, unless discard_changes is true. Work on a new output. Destructive page/security/redaction/XFA/attachment changes require explicit permission (xfa_to_static, and doc_flatten of an XFA form's fields, remove its XFA template, data and scripts; text_edit refuses a rewrite that would remove text drawn as a clipping path); do not drive the separate desktop ui channel. JavaScript is on by default; since 0.21.0 doc_open runs a form's document-level and /OpenAction scripts, doc_save its Will Save actions first (their changes are saved; see will_save) and doc_print its Will Print actions. Such unasked scripts may only ask for highlight, zoom, focus or a page, and script requests (print, url, submit) come back as data; before opening an untrusted file, call js_enabled with enabled false. It is on again in every new server session, and with it on, doc_open's reply is already dirty with the undo step "Run JavaScript" (observed). js_document_scripts lists only named document-level scripts and returned none for an /OpenAction script, so check doc_info has_javascript instead; a saved copy keeps the scripts (observed). Roots check file paths only: a doc_print job sent to a printer, a Keychain/Windows-store identity for sign_document and the installed programs some tools start are outside them: LibreOffice for Office inputs to doc_combine, doc_create_multiple and doc_batch's convert step (0.21.0; `PDFCRAFT_SOFFICE`, the PATH, then the usual install folders; a private temporary folder, macros off, stopped after 120 s or 512 MB) and Tesseract for OCR engine tesseract or auto and for ocr_status (0.19.0; `PDFCRAFT_TESSERACT`, else the PATH; a minimal environment, 120 s). The default ocrs engine is built in.

## Durable verification

doc_open's reply carries no warnings: read doc_info after every open, input or reopened output, for repairs, unreadable_objects and warnings (a truncated file opened as a shorter document with only those fields to show it; observed). Reopen the saved PDF and check page count, text and rendering. For redactions, use a genuine content-removal audit and inspect sanitized output; visual rectangles are not enough. redact_mark removes nothing until redact_apply, whose verification pass must succeed; it also removes the replies of the comments it removes and clears image pixels under the marks, and it refuses, leaving the document unchanged, a tagged PDF whose structure tree it cannot clean completely; then check doc_hidden_info and doc_revisions. redact_apply refuses a mark with no readable area before changing anything, and removing hidden information strips metadata, private data, embedded files and actions from every object that holds them and refuses content it cannot decode in full instead of keeping it. redact_apply removes a vector path a mark overlaps whole rather than clipping it, and unlinks Type 3 glyph programs and fonts nothing draws any more, refusing a document whose Type 3 fonts it cannot clean safely. Since 0.21.0 it also drops Info and XMP metadata that repeats the removed text and counts the bookmarks, attachments, comments and other XMP still holding it in still_holding (doc_remove_hidden removes them), and a page that can't be read in full makes hidden-text and hidden-layers removal fail there. Sanitizing the hidden-layers category (doc_remove_hidden, doc_optimize's discard) decides what an optional-content membership dictionary hides by evaluating its /P policy and /VE expression against the default configuration: content under an AllOff or Not rule is removed even when every layer is on, an expression it cannot evaluate (malformed, cyclic or too deep) counts as hidden unless it names only layers that are on, and an off layer that visible content still refers to stays in the configuration; doc_hidden_info counts that content and the image, form and undecodable or too deeply nested XObjects the pass would drop, so its hidden-layers count can be non-zero with no layer switched off. The helper only checks PDF markers, not validity or confidentiality.
